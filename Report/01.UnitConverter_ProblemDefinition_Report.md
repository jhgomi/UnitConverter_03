## 1. Executive Summary

Python 실습 **Unit Converter** CLI에서, 학습자가 `단위:값` 입력으로 meter / feet / yard 변환 결과를 확인할 때 **README에 적힌 기대와 실제 프로그램 동작이 어긋나** 신뢰하기 전에 **같은 입력을 반복 실행**하고 **잘못된 값을 직접 넣어 검증**하는 비용이 발생했다.

본 문서는 Rob Fitzpatrick **Mom Test** 인터뷰(6회 Q&A)에서 수집한 **과거 사실**만을 근거로 문제를 정의한다. 솔루션(OCP·JSON·앱 등)은 §5 표면 문제로 분리하고, §4 진짜 문제 1문장을 PRD·세션 3 워크북의 입력으로 고정한다.

## 2. 프로젝트 맥락

### 2.1 과제 개요 (README)

| 항목 | 내용 |
|------|------|
| **입력** | `단위:값` (예: `meter:2.5`) |
| **출력** | 해당 값을 지원 단위 전체로 변환 (예: `2.5 meter = 8.2 feet`) |
| **지원 단위** | meter, feet, yard |
| **변환 비율** | `1 m = 3.28084 ft`, `1 m = 1.09361 yd` |
| **품질 기대** | OCP · SRP · 입력 검증(음수, 형식, 미지원 단위) · 테스트 |

### 2.2 시작 코드 상태 (`UnitConverter.py`)

- 단일 `main()`에 파싱·변환·출력이 혼재
- `if/elif`로 단위 분기 — 확장 시 수정 범위 큼
- 형식·숫자 오류는 일부 처리, **음수 검증 없음**
- 출력 소수 자릿수 **정책 없음** (raw float 출력)

| Q1 | 최근 사용 시점·상황 | **2026-06-11 오후**, README 직후 `meter:2.5` 실행. `8.2021 feet` vs README `8.2 feet`. **3회** 재실행 → 매번 동일 | 증거 1 |
| Q2 | 결과가 달랐다면? | **가정 거부**. 실제로 3회 동일. README 차이 **메모장 기록** | Mom Test 방어 |

| Q6 | 인터뷰 종료·요약 | 워크북(페르소나·과거 사실·표면·진짜 문제) 확정 | — |

### 3.4 관측된 입·출력 (실측)

| 입력 | 출력 / 결과 |
|------|-------------|
| `meter:2.5` (×3) | `2.5 meter = 8.2021 feet`, `2.5 meter = 2.734025 yard` |
| `feet:8.2` (×1) | `8.2 feet = 2.4999875686 meter`, `8.2 feet = 2.7333333333 yard` |
| `meter:abc` | `Invalid number: abc` → 종료 |
| (빈 입력) | `Invalid format. Use unit:value (ex: meter:2.5)` → 종료 |
| `meter:-2.5` | `-2.5 meter = -8.2021 feet`, `-2.734025 yard` (차단 없음) |

### 3.5 README vs 실측 갭

| 항목 | README 기대 | 실측 (`UnitConverter.py`) |
|------|-------------|---------------------------|
| `meter:2.5` → feet | `8.2 feet` | `8.2021 feet` |
| `meter:2.5` → yard | `2.7 yard` | `2.734025 yard` |
| 음수 입력 | 검증(차단) 요구 | **통과·변환** |
| 출력 일관성 | (명시 없음) | 3회 동일 — **비결정성은 없음** |

## 4. 문제 정의 (확정)

### 4.1 증거 3줄

1. `meter:2.5`를 **3회** 실행해 결과 동일 여부를 확인했고, 출력 `8.2021 feet`가 README 예시 `8.2 feet`와 달랐다.
2. `feet:8.2` 실행 후 README와 소수점 차이를 **메모장에 기록**했다.
3. README는 음수 검증을 요구하지만 `meter:-2.5`는 **에러 없이** 변환 결과가 출력됐다.

### 4.2 진짜 문제 (한 문장)

**README에 적힌 기대(반올림 예시, 음수 차단)와 실제 프로그램 출력·동작이 일치하지 않아, 변환 결과를 믿고 쓰기 전에 같은 입력을 반복 실행하고 직접 잘못된 값을 넣어 검증하는 데 시간을 썼다.**

### 4.3 표면 문제 (금지 — 솔루션 섞인 문장)

| 표면 문제 | 왜 금지인가 |
|-----------|-------------|
| 「**단위 변환 프로그램**이 필요해요」 | 제품·기능 이름이 문제 정의에 섞임 |
| 「**JSON/CSV 출력**이 있으면 좋겠어요」 | 추가 요구사항 — Mom Test 증거 없음 |
| 「**OCP·테스트**를 넣으면 해결돼요」 | 구현 수단 — 행동·비용 증거 아님 |

→ 위 문장들은 **원하는 기능**이지, 인터뷰에서 확인된 **과거 행동·비용**이 아니다.

### 4.4 문제 → 요구 방향 (솔루션 최소화)

| Mom Test에서 드러난 것 | 요구 방향 (WHAT, not HOW) |
|------------------------|---------------------------|
| 3회 재실행 | **한 번 입력으로 신뢰 가능한 동일 결과** |
| README vs 출력 불일치 | **문서화된 정밀도·비율과 일치하는 출력** |
| 음수 무차단 | **README 검증 기대와 동일한 거부 동작** |
| 수동 오류 입력 테스트 | **자동화된 검증(Test Loop)으로 대체** |

## 5. 세션 3 워크북 연계 (초안)

### 5.1 주제 (한 문장)

**길이 값(`단위:값`)을 한 번 입력했을 때, README에 적힌 변환 규칙과 검증 기대에 맞는 결과만 일관되게 돌려받을 수 있어야 한다.**

### 5.2 R-G-I-O

| | 내용 |
|---|------|
| **Role** | 길이 단위 변환 CLI — meter / feet / yard |
| **Goal** | 재실행·수동 대조 없이 README 기준 결과 신뢰 |
| **Input** | `단위:값` (예: `meter:2.5`) |
| **Output** | 전 단위 변환 결과 또는 명확한 오류 메시지 |

### 5.3 성공 기준 (Mom Test 연결)

| # | 기준 | 연결 증거 |
|---|------|-----------|
| SC-1 | 동일 입력 → 출력 **바이트 동일** | 3회 재실행 |
| SC-2 | README **정밀도**(`8.2 feet`) 일치 | `8.2021` vs `8.2` 메모 |
| SC-3 | 음수·형식·미지원 단위 → **변환 없이** 오류 | `meter:-2.5` 무차단 |
