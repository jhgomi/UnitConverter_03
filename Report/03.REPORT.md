## 3. 워크북

### 3.1 주제 한 문장 (Mom Test 기반, 솔루션 최소화)

**길이 값(`단위:값`)을 한 번 입력했을 때, README에 적힌 변환 규칙과 검증 기대에 맞는 결과만 일관되게 돌려받을 수 있어야 한다.**

### 3.2 R-G-I-O

| | 내용 |
|---|------|
| **Role** | 길이 단위 변환 CLI — meter / feet / yard 변환·입력 검증 |
| **Goal** | **재실행·수동 대조 없이** README 기준 변환·검증 결과를 신뢰 |
| **Input** | `단위:값` (예: `meter:2.5`, `feet:8.2`) |
| **Output** | 지원 단위 전체 변환 결과. 잘못된 입력 시 **명확한 오류 메시지** 후 종료 |

**변환 규칙:** `1 m = 3.28084 ft`, `1 m = 1.09361 yd` (feet↔yard는 meter 기준)

### 3.3 성공 기준 3개 (Mom Test 증거 연결)

| # | 성공 기준 | 연결 증거 |
|---|-----------|-----------|
| SC-1 | 동일 입력 여러 번 실행해도 출력 **바이트 단위 동일** | 3회 재실행 확인 행동 제거 |
| SC-2 | 변환 결과가 README 비율·**문서화된 정밀도**(`8.2 feet`)와 일치 | `8.2021` vs `8.2` 메모 문제 해소 |
| SC-3 | 음수·형식 오류·미지원 단위 → **변환 없이** 오류 메시지 | `meter:-2.5` 무차단 문제 해소 |

## 4. 8계층 — 이번 세션에서 만드는 것만

### 4.1 Rule

- Mom Test 진짜 문제: README 기대 ↔ 실제 동작 불일치 제거
- 변환 비율 README 고정값 (3.28084, 1.09361)
- 출력 소수 자릿수 정책 명시 (feet/yard 소수 1자리, meter 입력값 유지)
- 음수·형식 오류·미지원 단위 → 변환하지 않고 오류 메시지
- OCP: 새 단위 추가 시 기존 로직 수정 최소화
- SRP: 파싱 / 검증 / 변환 / 출력 분리

### 4.2 Command

1. `UnitConverter.py` 구조 분석 → 책임 분리 설계
2. meter/feet/yard 변환 (meter 기준)
3. 입력 검증 (형식, 숫자, 음수, 미지원 단위)
4. 출력 포맷터 (README 예시 정밀도)
5. pytest → SC-1~3 → Test Loop

### 4.3 Skill (선택)

- **이름:** `unit-converter-test-loop`
- **트리거:** 변환·검증·포맷 변경 시
- **완료:** SC-1, SC-2, SC-3 green

### 4.4 Test Loop

```
[Red]  Mom Test 증거 TC 고정
[Green] 최소 구현
[Refactor] OCP/SRP (TC green 유지)
[Repeat] pytest 전체 실행
```
